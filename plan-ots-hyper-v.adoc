= ONTAP Select 的 Hyper-V 儲存設備需求
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
在 Hyper-V Hypervisor 上設定 ONTAP Select 時，ONTAP Select 會將虛擬機器（VM）和虛擬磁碟儲存在 Hyper-V 主機上的本機 Volume 中。



[[basic-requirements-and-restrictions]]
== 基本要求與限制

以下組態要求和限制適用於 Hyper-V 主機上的 ONTAP Select 儲存資源池：

* 儲存資源池必須是已指派磁碟機代號的 NTFS 或 ReFS Volume。Deploy 公用程式透過磁碟機代號識別儲存資源池。
* 叢集共享 Volume 不支援作為儲存資源池。
* 網路檔案共用和遠端 UNC 路徑（例如 SMB 3.0）不支援作為儲存資源池。
* ONTAP Select 無法發現僅掛載到資料夾路徑的 Volume，因為該 Volume 沒有磁碟機代號。
* 如果 Hyper-V 主機將 LUN 格式化為 NTFS 或 ReFS 並指派磁碟機代號，ONTAP Select 即可透過 FC、FCoE 或 iSCSI 使用外部儲存陣列上的 LUN。ONTAP Select 會將此類 Volume 視為本機主機儲存設備。與 ESXi 搭配使用的 ONTAP Select vNAS 模型不適用於 Hyper-V。
* 如果 Storage Spaces 虛擬磁碟格式化為 NTFS 或 ReFS 並指派了磁碟機代號，則可以容納儲存資源池。但是，軟體 RAID 無法使用屬於 Storage Spaces 資源池成員的實體磁碟。
* Hyper-V 組態無法辨識精簡配置的儲存設備。ONTAP Select 使用 Windows 報告的 Volume 容量。




[[best-practices]]
== 最佳實務做法

您應該遵循以下最佳實務做法：

* 為 ONTAP Select 網路定義專用網路介面卡、頻寬和虛擬交換器組態。將外部儲存設備流量（例如 iSCSI）放在分隔的介面卡上。
* 將儲存資源池 Volume 專用於 ONTAP Select。請勿在同一 Volume 上放置其他 Hyper-V 虛擬機器或 Windows 工作負載，也不要將 Windows 開機 Volume 用作儲存資源池。
* 設定 Volume 大小，使 ONTAP Select 不會使用其全部容量。
* 為外部儲存陣列設定 Windows MPIO，使 LUN 透過備援路徑呈現。
